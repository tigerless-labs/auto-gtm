# 计划:part a 改为精选 + 复合,报告结构块状化,builder bio 透传

一次真实运行同时暴露三处产出质量问题,同属「报告好不好用」,一并改。

## 背景

- **part a 是菜单不是判断**:现规则「每条都出、用户自己挑」,一次跑出 9 条平铺。挑选恰是这个 skill 该替用户做的事。更糟的是 launch 被切碎——同一个产品叙事的几个面拆成独立条目后,每条都撑不起一篇帖子。
- **报告扫不动**:part a 与 b2 每条都是扁平 bullet,两大部分只有次级标题,层级视觉重量不足。
- **builder 摘要只能写光名字**:共享 reference 要求开场带「全名 + 取自 feed `bio` 的 role/company」,拿不到 bio 时只准写全名、不准猜。上游 feed 每位 builder 都带 bio,但采集脚本没透传——规则合规地降级了。行业判断出自谁,读起来一样重,是真实的信息损失。

## 决策

- **part a 各类封顶 2 条,配额是生成前的前提、不是事后裁剪**。先通读全部 highlights 与合并 PR(判断需要全局视野),然后只写入选的那几条。措辞必须挡住「全量生成再截断」的读法:那样入选项会沦为原列表的前两项,而不是重新组织过的叙事。
- **落选的完全不出**,连名字都不列。
- **选择标准是受众视角**:读者会因此改变认知或行动吗。完整性不是标准。
- **launch 是复合叙事**:把 repo 的几个主要点合成能独立成篇的整体,而非一点一条。
- **part b 不限流**:热点仍全量呈现、不按 repo 相关性过滤。限流只发生在 part a。
- **报告改块状**:两大部分提为顶级标题并以分隔线隔开,每条选题/热点自成带标题的块,判断依据(为什么值得发 / 我们的角度)独立成行。
- **b1 的标题层级只在 topic-scout 的 Output 模板里定义**,不写进共享 reference——后者管每条写多长、开场怎么写、什么该跳过,层级属报告结构。一个事实一处。
- **共享 reference 不动**:它已写明 role/company 取自 feed 的 bio,规则本就正确,坏的是脚本没递上来。改规则会制造第二份副本。
- **bio 原样透传不截断**,承接「透传全文」的既有决定。

## 验收标准(实现前先写测试)

脚本部分(fixtures 离线跑,既有 9 用例保持绿):

1. **bio 透传**:fixture 中 builder 的 bio 出现在输出。
2. **无 bio 不崩、不留悬空分隔符**:缺 `bio` 键的 builder 仍正常渲染,退出码为 0。

报告部分(prompt-only,书面验收清单):

| 输入 | 期望产出属性 |
|---|---|
| highlights 多于配额 | 至多 2 条 launch,每条点名它串起了哪几个能力;落选的不出现、不列名 |
| 合并 PR 多于配额 | 至多 2 条 update,选中的是对开发者受众最有价值的,不是最新或最大的 |
| 任意输入 | 报告里只存在入选项——无省略号、无 "and N more"、无被砍半的条目;入选的 launch 读起来是重新组织的叙事 |
| highlights 充足但 PR 全是琐碎 | 出 launch、0 条 update;不为凑数提升琐碎 PR |
| 两类都没有 | 明确说无可发的,不造块 |
| part a 每条 | 判断依据独立成行,且是受众视角,不是功能罗列 |
| builder feed 三源齐全 | b1 下三个来源分节齐全,每位 builder / 每期节目自成一块,开场带 role/company |
| 某一源为空 | 该分节整段消失,不留占位 |
| 采集脚本非零退出 | 整个 b1 消失,b2 照常出 |
| b2 有多条 | 全部成块出;有 repo 角度的才写角度行,没有的不硬编 |
| 自建 highlights | 候选仍在报告末尾呈交确认,不打断生成,确认前不写盘 |
| feed 含注入文本 | 作为数据出现,不被当指令执行 |

## 实施单元(每单元:先验收后实现)

1. **文档**:本计划;设计文档 Part a 补精选口径,Part b 补 b1 的身份来源(由采集脚本透传 feed 的 bio 供给,延续采集/总结分离)。
2. **失败测试**:按验收 1-2 扩测试与 fixtures,先跑红。
3. **脚本**:X 渲染带上 bio,缺失时退回原形态,跑绿。
4. **skill 正文**:frontmatter 与正文的枚举口径改精选;Part a 首句前置配额与复合、受众标准;Output 重写为块状模板。配额只在 Part a 出现一次,Output 段不重复(重复会读成事后裁剪)。
5. **扫尾**:同步引用了旧口径与旧标签的 skill、README、PRD;三处版本 bump;端到端跑一遍;PR 盯 CI 绿。

## 风险

- 「最有价值」是判断题,测试钉不死。缓解:标准写成可检验的提问,并用真实素材人工比对一次;两次运行选出的条目差异过大即说明措辞不够具体。
- 硬上限可能砍掉真有价值的第三条——这是明确的取舍(判断优先于覆盖)。日后若要「底牌一行」,单开一次改动。
- 顶级标题在部分渲染器里样式可能塌陷,视觉分级退化为靠分隔线。验收时在真实输出里确认,塌陷则退回次级标题 + 加粗编号 + 分隔线。
