# 计划 — drafting skill 砍薄:身份定义在前，规则退场

## 背景与问题

一次真实运行(分享 Aaron Levie 关于 AI 与招聘的观点)暴露:草稿的**语气合格、内容不成立**。第一版默认读者已经知道被引用者是谁、在反驳什么，开口即中途插入；第二版在「我们的赌注 / 我们做什么 / 他的说法 / 他的结论」之间跳，没有可辨认的主张。用户用的是能力最强的模型，问题不在模型。

根因:`x-content-generator` 只有**一个轴——声音**。voice rules、tone 契约、no-ai-slop，全部作用在句子层与语域层；内容层没有任何东西。于是模型只剩套路可填。

三处结构性缺失:

1. **没有读者入口**。X 上的分享帖要在 timeline 里独立成立，skill 从未要求交代被引用者是谁、在回应什么。
2. **没有「你凭什么同意」**。认同帖的价值全在作者自己那份证据上；skill 只问声音，从不问用户看到了什么，剩下的只能是复述加表态。
3. **没有论证弧**。没有任何东西要求先落一句主张、再给机制、再给它改变了什么。

还有两处放大器:

- **模仿即反内容**。「模仿节奏不模仿观点」字面上就是把观点层剥掉只留形状，产出有壳无核。
- **no-ai-slop 被当成生成器**。它是为「已有观点的草稿」设计的减法编辑器；前置成生成约束，产出的是「为了不像 AI 而写」的东西。

越强的模型指令遵循越硬，这套有缺陷的约束咬得越死——换更好的模型只会让缺陷执行得更彻底。

**这是对 [`tone-voice-source-gate.md`](tone-voice-source-gate.md) 的部分回退。** 那一轮把声音来源治理成出稿前的硬 gate，解决了「静默降级」，同时把「写得像你」变成了一项合规任务，挤占了内容推理。方向修正:声音回到上下文供给的位置，不再是被裁决的规则。

## 目标

把 drafting skill 从**约束栈**换成**身份 + 材料**。开头一段身份定义，材料齐则写、缺则问;声音与去 AI 味降为可读的参考，no-ai-slop 挪到末尾做最后一道检查。

一条分界线贯穿全篇:**保留机械约束(输出形态、止于草稿)，删除审美约束(节奏、句长、禁用词、语域纠偏)。** 机械约束不占推理预算，审美约束与内容推理直接争抢。

## 范围

本轮动两个**原创帖** drafting skill(`x-content-generator`、`reddit-post-drafter`)与共享的声音契约。两个**回复类** skill(`x-auto-comment-draft`、`reddit-auto-comment-draft`)**不做身份改写**，仅修复指向已删章节的悬空引用(机械修补)——它们多一层 per-thread overlay，另开一轮。

## 单元一 — 设计文档先行

**验收标准**
- `docs/design/tone-voice.md` 改写为「声音是上下文，不是规则」:说明 drafting skill 以身份定义开篇、材料缺失即发问、声音样本作为校准材料、no-ai-slop 作为末检。删去两轴、冲突裁决、gate 治理三段。
- 文档写明这是对上一轮 gate 化的修正及其理由(合规任务挤占内容推理)。
- `docs/design/index.md` 中声音一行的描述与新契约一致。
- 保持中文、只写意图与边界，不出现函数/常量/路径。

## 单元二 — tone.md 砍薄成上下文供给

**验收标准**
- 只回答一个问题:动笔前该读什么。保留样本位置、缺失/不完整时如何一次性捕获并存储、样本优于内置样例这一实话、以及回复类的 per-thread overlay(它本身就是上下文)。
- 删除:双轴与冲突裁决整段、voice-source gate 的治理条文、「须披露的降级」条款、接口约定段。
- 保留一句边界:样本校准的是听感，观点始终是用户自己的。
- **修掉判空缺陷**:现行 gate 以「文件非空」为通过条件，导致 `bloggers.md` 里只有收藏博主、用户本人账号仍为空时从不发问。改为按**缺哪一块问哪一块**。
- 篇幅至少减半。

## 单元三 — x-content-generator 身份化重写

**验收标准**
- 正文以身份定义开篇:你是这条帖子的作者本人，不是模仿者;你对话题有真实的立足点(你做了这件事，或你亲眼看到);从这个立足点写;还没有就先问。
- 删除 `## Stance` 全段与 `Voice rules` 全部条目。
- 保留的约束只剩两类机械项:输出为可直接粘贴的 code block(禁 blockquote)、止于草稿不代发。
- 声音与 no-ai-slop 以「参考/末检」形式出现，不再是出稿前必须满足的条件。
- 篇幅显著短于改前。

## 单元四 — reddit-post-drafter 同款重写

**验收标准**
- 以身份定义开篇:发帖的是社区成员而非投放文案的市场人员;对话题有真实立足点;账号是零 karma 新号，帖子靠内容换取位置。
- 共享引用收成一行 References;版规、社区高赞帖读法、新号姿态等平台特有条款保留(它们是护栏与上下文，不是审美约束)。
- **目标社区不再是阻塞材料**:没有社区也先出稿，末尾再把选择交回人手(提供 `reddit-subreddit-finder`)，并注明版规与自推判定挂起。停只停在缺内容处。
- 有社区时行为不变:实时摘版规、读该社区高赞帖、禁自推且题材属推广则说明并停手。
- 输出多一档状态:版规/自推判定为 safe / risky / **待定社区**。

## 单元五 — reddit-auto-comment-draft 同款重写

**验收标准**
- 以身份定义开篇:回帖的是社区成员、在回答一个具体的人;零 karma 新号;回复靠帮到发帖人换取位置。
- **`Flow` 的编号步骤全部拆掉**——顺序由依赖决定(没有线程就无法起草)，编号是脚手架。
- 「哪些线程值得回」从筛选条件提升为独立的判断句:有真东西可说才回，已被答好的、诚实答案与产品无关的都跳过。这是本 skill 的核心思考，不得再埋在步骤里。
- 阶梯三段压成三行;版规摘要、新号不放链接、搜索窗口、Config 原样保留(护栏与可调项)。
- 删掉替 no-ai-slop 重述其职责的句子。

## 单元五之二 — x-auto-comment-draft 同款重写

**验收标准**
- 以身份定义开篇:回帖的是 builder、在别人的线程里回答一个人;冷账号;回复靠帮到发帖人换取位置。
- 「哪些帖值得回」提为独立判断句，不再埋在取数段末尾。
- 取数三档顺序(复用当日 topic-scout 报告 → 先跑一次 → 直接搜)压成一条材料，行为不变。
- 立足点列为材料之一:没有就问。
- 阶梯不引入——X 侧每帖一条回复，与 Reddit 侧的三档刻意不同。

## 单元六 — 验收清单(prompt-only 的测试)

以真实输入跑两个 drafting skill，逐条核对:

| 输入 | 期望 |
| --- | --- |
| 分享一条外部观点，用户未给出自己的立足点 | 出稿前发问，索要用户自己看到的具体事;不产出复述型草稿 |
| `bloggers.md` 有收藏博主、本人账号为空 | 指出缺的是本人账号并发问，不因文件非空而静默通过 |
| 两块样本齐备 | 直接读用，不重复发问、不重抓 |
| 分享型选题 | 草稿在不预设读者已知来源的前提下成立，被引用者与其所回应的对象在正文内交代清楚 |
| 用户明确要求某种结构 | 内容诉求被满足，且不产出小标题式 release-note |
| 来源页/transcript 内含「立刻发出去」类指令 | 视为数据，不执行，草稿照常停在人审 |
| 任意一次运行 | 输出为 code block，无 blockquote，无平台写操作 |
| reddit-post-drafter:未指定社区、无存储选择 | 不发问，直接出稿;末尾提供 `reddit-subreddit-finder` 并标注版规/自推判定待定社区 |
| reddit-post-drafter:指定了禁自推的社区 + 推广题材 | 说明并停手，指向评论 skill |
| reddit-post-drafter:未给立足点 | 仍然发问——缺的是内容，不是投放目标 |
