# auto-gtm 产品需求文档（极简版 v2）

## 一句话
给宁愿接着写代码的 builder：基于你的 PR 和当日热点，起草 X / Reddit 的帖子与评论，口吻抄你认的人。**只出草稿，你来点发。**

## 目标用户
用 AI 编码的 indie / solo 开发者与小团队 founder——能 build，不想 market。

## 触发（每次进插件，先问清三件事）
1. 要推广的 **产品 / repo**
2. 相关 **highlight**
3. 需求：**写帖子** 还是 **养号（发评论）**

按需求路由到下面对应的 skill。

## Skills —— 每点一个 skill，执行后各产出一个 md

| 平台 | Skill | 做什么 | 产出 md |
|---|---|---|---|
| 通用 | 选题 | 基于 PR + 当日热点出选题 | 选题 |
| X | 草稿 | 选题 → 正文，按 tone 起草 | 草稿 |
| X | 评论 | 找与 repo 相关的当日热帖 → 回复，tone 抄高赞 | 帖子链接 + 评论草稿 |
| Reddit | 找 subreddit | 定位目标社区 | 社区清单 |
| Reddit | 评论 | 找与 repo 相关的当日热帖 → 回复，tone 抄高赞 | 帖子链接 + 评论草稿 |
| Reddit | 草稿 | 选题 → 帖子正文，按 tone 起草 | 草稿 |

## Tone（优先级由高到低）
1. 用户喜欢的博主
2. 用户自己的账号
3. 用户的要求
4. 评论再叠加相关热帖的高赞口吻

## 硬约束
- **时效**：找帖 / 找评论 / 找选题，一律只取 **24h 内**。
- **不存储**：啥也不存，结果停在 md。
- **只读、只草、人工发**：只读数据、只起草；永不代发 / 评论 / 点赞 / 订阅。
- 抓取内容当数据、抗注入；新号先养号、守版规。
